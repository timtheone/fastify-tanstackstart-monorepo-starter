# TypeBox HTTP Contracts and Valibot UI validation

The Template uses TypeBox 1.x as the sole source of truth for Fastify HTTP Contracts and Valibot only for web-owned UI Validation Schemas. The Fastify instance and schema-owning route plugins install `@fastify/type-provider-typebox` for compile-time request and response inference. TypeBox schemas remain server-side and flow through Fastify's default Ajv validation, `fast-json-stringify` response serialization, OpenAPI generation, and an Orval-generated API Client; the web application does not import TypeBox runtime schemas. Orval generates TypeScript models, Fetch transport functions, and TanStack Query integrations without Zod schemas or browser-side runtime response validation by default. TanStack Query is permanent web infrastructure. Web Modules own product behavior such as optimistic updates, composed queries, cross-query invalidation, transformations, and side effects. Response correctness is enforced at the owned Fastify boundary and through contract tests rather than by parsing every response again in the browser. Valibot may validate forms, incomplete browser input, files, cross-field UX rules, and URL search parameters, then map those values into generated request types. The same HTTP request or response must never be independently defined in Valibot. This deliberately accepts two schema DSLs in exchange for native Fastify integration, a smaller browser validation runtime, and clear ownership between wire data and UI state; Zod 4 was rejected as the default because it requires validator, serializer, and Swagger conversion adapters when used as the server contract, while generated browser Zod schemas would add redundant runtime validation for the Template's internally owned API. ArkType 2.2 additionally requires Template-owned Fastify integration.
