# RFC 9457 errors for the First-Party API

Every non-success response owned by the First-Party API uses a TypeBox-defined RFC 9457 Problem Details contract, with `type` as the stable machine-readable problem identifier and a structured `errors` extension for request-validation failures. A central Fastify error handler maps framework validation errors, known application failures, and unexpected exceptions into that public representation, allowing OpenAPI and Orval to expose consistent failure models without leaking implementation details. Orval's generated Fetch client throws on non-success responses, so TanStack Query receives an error state while callers retain the HTTP status and structured problem body through the generated error's `status` and `info` properties. Better Auth-owned endpoints retain Better Auth's native error protocol because its client owns that external boundary; they are not normalized by the application's error handler.
