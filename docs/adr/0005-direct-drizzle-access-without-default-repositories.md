# Direct Drizzle access without default repositories

Application operations accept an injected Drizzle database or transaction executor and may query or mutate any available schema; the Template imposes no table-ownership policy between Modules. A top-level application operation owns the transaction when its behavior requires several changes to succeed atomically; Fastify routes never start transactions, internal helpers accept the active executor, and single-query operations use no explicit transaction. The Template does not create repository interfaces and pass-through Drizzle adapters merely for mocking; database-backed behavior is verified against disposable Postgres instead. This deliberately couples application operations to Drizzle and Postgres in exchange for simpler transactions, faithful tests, and less indirection. A persistence seam is introduced only when a real second adapter or materially deeper interface justifies it.
