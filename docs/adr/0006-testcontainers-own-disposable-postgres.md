# Testcontainers owns disposable Postgres

Docker Compose provisions only the persistent development PostgreSQL service. Vitest integration and Playwright E2E commands use `@testcontainers/postgresql` to start one fresh container per command from a pinned PostgreSQL image, apply the same checked-in Drizzle migrations used outside tests, distribute its dynamically allocated connection URI, and explicitly stop it after all clients and application processes close. Database-backed Vitest tests and Playwright tests run serially by default and reset application state between tests without removing migration history; pure Vitest projects remain parallel. Documentation may describe per-worker databases or containers as a later scaling option, but the Template prioritizes deterministic isolation over initial throughput. Cross-run container reuse is disabled so every run starts from known state, with Testcontainers' resource reaper retained as fail-safe cleanup. Vitest uses runner global setup, while an outer E2E harness owns PostgreSQL and the application processes before invoking Playwright; this keeps the live container handle and cleanup responsibility in one process. The accepted constraint is that local and CI test runners need access to a Docker-compatible API.
